# ADR 0005: WebDAV readiness, reservations and credentials

Status: accepted design; no mobile sync implementation or interoperability evidence yet. Uses the existing WebDAV protocol, not a new uploader. Phase 4 acceptance remains required for the complete release.

## Evidence and scope

Baseline vxcore `c3319ca9a7dfd5432cad1f7c35de6be099fc87bf`: [public phased sync ABI](../../third_party/vxcore/include/vxcore/vxcore.h), [sync guide](../../third_party/vxcore/src/sync/AGENTS.md), [C wrapper](../../third_party/vxcore/src/api/vxcore_sync_api.cpp). Desktop `f8026adb4c43f78d90251148e24b6e72ca28f3d7`: [service contract](https://github.com/vnotex/vnote/blob/f8026adb4c43f78d90251148e24b6e72ca28f3d7/src/core/services/AGENTS.md), [classifier implementation](https://github.com/vnotex/vnote/blob/f8026adb4c43f78d90251148e24b6e72ca28f3d7/src/core/services/syncstateclassifier.cpp). These are compatibility references, not permission to copy Qt implementation into mobile.

Mobile enables only bundled-notebook `webdav`. Desktop also supports `git` and `jianguoyun`; preserve their stored routing but present them as unsupported on mobile, never register or rewrite them automatically. Query runtime capabilities through `vxcore_sync_get_capabilities`; require deferred-local-apply support for this route. Core owns remote bootstrap, UUID binding, journals, preflight, conflicts and recovery. Use `vxcore_sync_enable`, credential update and the phased APIs; use clone only if the backend advertises it. Do not infer WebDAV clone support from the existence of `vxcore_sync_clone_cancellable`.

## State facts and precedence

Derive state on startup/resume/open and after every operation from persisted `syncEnabled`, `syncBackend`, `syncRemoteUrl`, validated secure credential presence, and `vxcore_sync_is_registered`. Never persist an independent S-number. `vxcore_sync_is_ready` checks routing completeness only; it does not validate mobile support, vault contents, authentication or network reachability. Vault lookup errors are unknown/error facts, not “absent”; keep actions blocked with retry until resolved.

Apply base classifier precedence exactly: disabled -> S0/S6; enabled unsupported/missing backend -> S3; supported backend without URL -> S1; complete routing without credentials -> S2; then runtime absence/presence -> S4/S5.

| State | Facts | Mobile action |
| --- | --- | --- |
| S0 | Disabled/absent routing, no credentials; no runtime after reconcile | Enable / sync information |
| S1 | Enabled, supported backend, missing URL; credentials may exist | Complete routing without discarding existing secret |
| S2 | Enabled, supported backend + URL, no usable matching credentials | Supply credentials |
| S3 | Enabled, backend missing or unsupported, regardless of URL/credentials | Explain unsupported routing; do not mislabel as missing URL or automatically migrate |
| S4 | Complete enabled routing, matching credentials, no runtime registration | Async reconcile/enable; surface actual failure, permit retry |
| S5 | Complete enabled routing, matching credentials, runtime registered | Ready/configured, **not connected/authenticated now**; manual sync allowed |
| S6 | Disabled with orphan credentials; no runtime after reconcile | Idempotent vault cleanup or explicit re-enable after pending delete settles |
| S7 | Busy overlay: queued/running sync or pending vault transaction | Preserve underlying base facts, display progress and prevent conflicting operations |

The pinned desktop classifier's `classify()` emits S7 only when base state is S5 and in-progress; its broader service contract counts vault work as busy. Mobile retains base state plus independent busy facts so an S4 reconcile/S6 deletion cannot incorrectly appear idle. Unexpected runtime registration with disabled/incomplete/unsupported routing is reconciled by runtime unregister and reported if that fails, not promoted to S5.

Foreground automatic sync obeys per-notebook `autoSyncEnabled`; use one coalescing trigger key for manual, automatic and post-reconcile work. Auto requests follow the configured consumer cadence, with a pending trailing-window timer absorbing a burst rather than restarting on every edit. Manual bypasses delay, not readiness/gates. Successful reconcile may trigger one freshness check (initial two-minute threshold, matching desktop); rapid resumes coalesce. Timers retire on close/disable/shutdown. No guaranteed background execution, backend timers or speculative online state.

## One operation, seven publication stages

Use ADR 0002's owner thread, bounded network workers, per-notebook operation lease and IO gate. Its concurrent error-storage prerequisite applies before network/owner overlap. Every operation owns request ID, notebook/session generations, sync cancellation token, deadline and reservation state. Core cancellation token APIs are real; the asynchronous host/reservation messages below are **proposed mobile protocol**, not public core APIs.

1. **Admit.** Validate readiness, capability, notebook lifecycle and retirement/recovery preflight. One item owns the whole round trip. Resolve pending core recovery before fresh credential ingress or sync. Do not use composite `vxcore_sync_trigger` on this route: it cannot insert the editor handshake and risks duplicate lifecycle completion.
2. **Stage.** Acquire G after earlier admitted local writers; call `vxcore_sync_stage_only`. Snapshot only durable notebook state, never force-save editor text. Release G before network; new normal saves may resume while the network phase is in progress.
3. **Network.** `vxcore_sync_network_phase` runs on W without G. Incoming deferred bytes remain private; core owns protocol concurrency and recovery. Progress is copied/coalesced and cancellation reaches the operation token via the independent control path.
4. **Reserve and drain.** With no G held, request an application/editor reservation. Because no public pre-apply changed-path query is assumed, conservatively reserve all open sessions and writers in this notebook. Freeze clean views against edits/reload, retain dirty text, suspend new saves/external-change checks/structural writers and collect dirty physical paths plus relevant sidecars, including active, pending, in-flight or failed sidecar writes. Drain already-running saves/writers without force-saving dirty participants. Paths are notebook-relative validated UTF-8 with `/` separators; no traversal, absolute/drive/UNC/backslash/NUL or invalid components. Use an operation-owned five-second deadline for reservation/save drain; timeout cancels before publication and releases the reservation, never pumps events or waits under G. Sidecar/attachment participants must join the same writer registry, not write around it.
5. **Apply.** After drain, O sets `vxcore_sync_set_apply_in_progress(...,1)`, then W acquires G and calls `vxcore_sync_apply_phase` with protected paths and token. Core preflights the cohort; do not duplicate its merges in Dart. The runtime flag is not persisted read-only state. Cancellation before dispatch prevents installation; cancellation after partial installation is not rollback. Keep the reservation until actual effects are reconciled.
6. **Refresh.** Release G. Capture `out_changed_paths_json` even when apply returns error, copy it, and always `vxcore_string_free` it. O invokes `vxcore_sync_refresh_notebook` while runtime/editor reservations remain valid; refresh installed paths even on partial failure. Reload only clean affected buffers after generation/base checks, refresh metadata/tree and notify actual working-tree changes. Dirty paths remain protected/conflicted, never reloaded over edits. If refresh fails, preserve core pending recovery and block unsafe editing of affected state with an actionable retry; do not invent a success timestamp or erase the original apply error. Retirement may replace the temporary reservation with an explicit recovery-required state rather than leave an invisible lock.
7. **Retire.** O clears runtime apply flag idempotently, retires editor/writer reservations, unfreezes safe sessions and releases leases. One completion owner emits exactly one terminal result with original error, changed paths, refresh status and per-file failures. Only complete successful network/apply/refresh and reservation settlement permits `vxcore_sync_set_last_sync_utc` on O; this timestamp is per-device local metadata, not portable config. Timestamp-write failure is visible and does not claim a recorded successful sync. No partial failure advances last-success.

Every error/cancellation/close/shutdown path runs retirement. Close first stops admission and cancels/wakes handshakes, then waits asynchronously for workers and mutation finalization while O remains available. A late reply checks operation/generation/phase and cannot create or revive a reservation. Free tokens/userdata only after native calls and callbacks finish. A five-second pre-apply handshake timeout is not permission to free an in-progress apply or abandon partial refresh.

## Secure credential transaction

Use iOS Keychain and Android Keystore-backed encrypted storage through a reviewed adapter. No plaintext fallback. The mobile vault key includes backend, canonical endpoint and notebook UUID; secret payload also validates those fields and schema version. WebDAV canonical URLs have no userinfo, query or fragment; mobile chooses HTTPS-only initially, with certificate/hostname validation. Password bytes are never trimmed. Core's actual `SyncCredentials` uses `extra.username` and `extra.password` for WebDAV; stale PAT-only header examples do not define a WebDAV secret schema. Keep secrets out of URLs, portable notebook JSON, editor JS, logs and error text.

Serialize vault and core lifecycle transactions for each notebook, including close/startup deletes. Pending vault work counts as busy. Use versioned secure entries plus a non-secret transaction marker recording operation identity, old/new entry references and phase; store no secret in the marker. All secret writes/reads are confirmed before reporting the corresponding phase complete. Never delete an entry simply because an in-memory presence cache is empty.

- **Enable/bootstrap:** validate routing and vault availability first; retain an existing usable entry. Securely stage candidate credentials, then call real core enable with transient credentials. On success promote the candidate's secure reference and finish persistence before reporting enabled. If persistence fails, preserve the original persistence error and compensate through successful core disable/unregister as appropriate, keeping existing notebooks/files and old usable credentials. Compensating failure is a recovery-required transaction, not successful rollback. Only delete newly owned staging roots after their leases and credential cleanup settle; never delete an existing notebook on enable failure.
- **Rotation, same endpoint:** retain old secure version throughout candidate staging/authentication. `vxcore_sync_set_credentials` authenticates via core initialization and verifies remote UUID before changing binding. Failed authentication leaves old runtime/baseline/secret usable. Promote new secure reference only after core success; if vault promotion fails, restore old runtime credentials and retain old secure entry. If restoration fails, block sync and surface recovery with both secure versions retained, not a false clean state. Remove old version only after successful promotion/settlement.
- **Endpoint change:** not a password rotation. Run `vxcore_sync_check_reconfiguration` and core provider-retirement recovery before changing binding. Preserve notebook/remote identities and journals; never wipe `vx_sync`, rename remote roots or implement retirement by filesystem deletion.
- **Disable:** core disable must succeed before clearing the active secure binding/deleting credentials. Core clears enabled/backend/URL but preserves auto-sync preference; successful disable never deletes remote data, journals or recoverable snapshots. Delete failure remains a reported orphan (S6), not successful secret removal. Failed core disable preserves routing and credentials. Complete only after cleanup outcome is known.
- **Close/startup/orphans:** follow desktop close cleanup semantics, including staged cloned notebooks; close does not delete remote data. Next reopen may require credentials again. Startup inspects persisted vault/transaction references, cleans disabled orphans idempotently, and reconciles enabled routing only after earlier deletes settle. Entry-not-found is successful deletion; locked/unavailable storage is retryable, never equivalent to absent. Crash recovery resumes/compensates the recorded phase; uncertainty retains both secure versions and blocks sync until core/endpoint binding is verified.

This is application transaction policy around existing core calls, not a claim that the C ABI offers a vault transaction. Same-notebook enable must wait for an earlier close/orphan deletion so it cannot erase newly stored credentials. Durable transaction references themselves require integrity/identity validation; diagnostics contain only redacted phase/error information.

## Capability-driven conflicts

Use `vxcore_sync_get_conflicts` after backend operation serialization; offer only core-supported resolutions via `vxcore_sync_resolve_conflict`. Backend conflict `canKeepBoth` controls Keep both, not a generic UI default: metadata/encrypted WebDAV conflicts cannot acquire that option from file extension guesses. Preserve unsupported/encrypted content; do not edit as plaintext. Local/remote recovery material remains under core control until resolution is acknowledged.

One bounded FIFO batch retains each selected path/resolution and per-file error, then runs the ordinary staged sync path. Distinct batches are not coalesced into a generic trigger and failed choices are not discarded. Revalidate stale conflict/path generations before resolution; a partially successful batch reports successes and failures separately, retaining unresolved choices and recovery data. No direct file replacement or custom merge/upload engine bypasses core capability checks.

## Rejected alternatives and observable acceptance

Rejected: persist S0–S7 as truth; use status polling as readiness; treat S5 as connectivity; force-save dirty editors before apply; hold G during UI handshakes/network; drop changed paths on error; mark sync success before refresh; overwrite vault credentials before authentication; delete secrets after failed disable; universal Keep both; a second Dart WebDAV implementation.

Acceptance requires a controlled endpoint and desktop/mobile fixtures, not personal notebooks:

- Predicate table covers unsupported-plus-missing-URL precedence, missing/locked vault, orphan secrets, unexpected registration and queued vault overlays. Resume/manual/auto produce no duplicate concurrent sync.
- Dirty notes/sidecars, clean sessions, concurrent pending saves and structural writers respect reservation/drain; network permits local saves without metadata races. Timeout/cancel/close at every phase leaves no leaked reservation or stale callback mutation.
- Partial apply installs are refreshed even on failure; dirty editor bytes and both recoverable conflict versions survive, with no advanced last-success timestamp.
- Failed enable persistence, bad-password rotation, vault lock/write/delete failure and process kill at each transaction phase preserve prior usable credentials or explicit recoverable state. Startup cleanup cannot delete a new generation's secret.
- Desktop -> mobile -> desktop round trips preserve UUIDs, notebook JSON, notes and assets; unsupported conflicts have no invented resolution choices. Certificate failures never downgrade.
- No build, test, formatter, network sync or device check was run for this ADR.
